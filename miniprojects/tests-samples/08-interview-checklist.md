# Interview-day checklist

## Before the call

- Send the requested ID securely as instructed and have the same document ready.
- Test Teams, screen sharing, camera, microphone, internet, editor, and font size.
- Turn off notifications and close private tabs, email, tokens, password managers, and unrelated applications.
- Prepare a clean coding folder with the permitted runtime; do not assume AI tools are allowed.
- Keep water, paper, and the vacancy's six SFIA skills nearby.
- Prepare six real STAR stories, one per skill. A story may cover several skills, but answer the skill asked.

## During the technical exercise

- Restate the task and ask about inputs, outputs, constraints, and failure behaviour.
- Narrate your reasoning and assumptions.
- Use clear names and small functions; avoid premature abstraction.
- Validate external input and never trust client-side authorisation.
- Cover happy path, boundaries, failure cases, and non-functional needs.
- Run or mentally trace examples often.
- If stuck, simplify, write pseudocode, and explain the next test you would make.
- Finish by summarising correctness, complexity, security, tests, deployment, monitoring, and next improvements.

## What to highlight from your CV

- React/Next.js/TypeScript delivery on high-volume and public-facing services.
- Jest, Playwright, Jasmine, React Testing Library, BrowserStack, and cross-device testing.
- WCAG, semantic UI, performance, responsive design, and user-centred delivery.
- REST API and third-party integration experience.
- Azure Logic Apps workflows as evidence of data integration, reliability, and support.
- Collaboration, code reviews, mentoring, and explaining technical choices.

## Important cautions

- Be exact about what **you** did versus what the wider team did.
- Do not claim production AWS/Kubernetes/Node expertise beyond your evidence. Show transferable knowledge and a learning plan.
- Never invent results. If no metric exists, explain observable impact and what you would measure now.
- Do not reveal client-confidential data when using past examples.
- Ask before using Copilot, ChatGPT, notes, or internet search during the exercise.

## Is getting an interview a good sign?

Yes. Your written evidence passed the sift strongly enough to be assessed at interview. It is not a guarantee, but it means the panel sees credible evidence against the essential criteria. The next step is to make that evidence specific, personal, and easy to score.
